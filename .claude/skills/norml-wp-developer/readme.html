Norml WordPress Copilot Advanced

v1.2.1

Connect the theme, GitHub, and server once; let the AI map the project; then develop and ship from a verified project contract.

For: WordPress developers working in CLI runtimesActs on: a local theme repo plus its GitHub and WordPress serverCLI · GitHub · SSH · WP-CLI
The problem

WordPress development context is often scattered across a laptop, GitHub, hosting notes, SSH config, and one developer's memory.

Advanced verifies those connections and stores the capability boundary, architecture, deploy contract, and work history inside the theme repo.

CLI only
Run it in Claude Code, Codex, or Gemini CLI. It requires GitHub, SSH, remote WP-CLI, and a local theme repo; it does not run in Desktop / Cowork.
What it does

The first scan proves the operating surface before development begins.

Connect the projectrequired
Verifies local Git, GitHub origin, production SSH, remote WP-CLI, and optional staging.
Map architecturegenerated docs
Combines read-only live WordPress evidence with a bounded local theme inventory.
Develop themesSage or inherited
Builds within the recorded stack and project mode.
Ship through GitHubgated
Branches, commits, CI/CD, staging QA, and production promotion.
Run in Desktopnot supported
Desktop / Cowork uses the REST/API Norml WordPress Copilot instead.

Boundary
No Claude Desktop / Cowork runtime; terminal and local filesystem are required.
No completed onboarding without a readable GitHub origin, production SSH, and remote WP-CLI.
No secret in chat, project config, .claude/, Git, or workflow source.
No production write without confirmation and verified backup acknowledgement.

For REST/API content work without server access, use Norml WordPress Copilot.
