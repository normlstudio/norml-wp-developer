## Project mode — what conventions apply

{{MODE}} mode means:

- **`sage`** — Norml-authored, Roots Sage + Acorn + Blade + Tailwind v4
  + Vite + Alpine + ACF Pro. Strict architecture. See
  `references/dev-conventions.md → Sage section` in the
  `norml-wp-developer` skill folder.
- **`inherited`** — non-Sage theme handed to us. Respect the existing
  architecture; apply framework-agnostic core principles
  (section/component/partial separation, ACF block registration,
  3-layer CSS) inside the existing theme. Never silently introduce a
  new framework. See `references/dev-conventions.md → Inherited
  section`.

## Connection details

Per-machine connection config lives at:

```
~/.config/norml-wp-developer/projects/{{SLUG}}.json
```

That file holds: theme root path, SSH aliases, host details, theme
paths on production/staging, deploy pattern.

**Never paste credentials into this CLAUDE.md or any committed file.**
SSH passphrases live in ssh-agent + OS Keychain. GitHub tokens live in
the OS secret store. Database passwords live in `wp-config.php` on
each environment (gitignored at the local end).

## Changelog protocol

The `.claude/changelog/` folder uses a rolling three-tier protocol —
see `changelog/README.md` for the full spec. Quick version:

- `daily.md` — today's raw entries, newest on top
- `weekly.md` — compressed past week
- `changelog.md` — long-term history

Claude appends to `daily.md` before closing any session that did
something durable (code change, deploy, decision, learning).

## Architecture docs

The `.claude/docs/` folder holds a 5-file architecture snapshot:

- `01-infrastructure.md` — server, PHP, MySQL, host config
- `02-application.md` — WP version, plugins, theme inventory
- `03-theme-architecture.md` — file layout, component patterns, ACF
- `04-content-structure.md` — CPTs, taxonomies, content counts
- `05-issues.md` — known issues, version mismatches, blockers

Generated by the `norml-wp-developer` skill's
`scripts/scrape-architecture.sh` (or the Windows PowerShell mirror).
Rescan refreshes `capabilities.md`, `architecture.md`, and the five-file
snapshot; refresh `weekly.md`
when something architecturally significant changes.
